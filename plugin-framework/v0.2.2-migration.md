## 一、primitives 导出面变更（本篇核心，逐版实测）

`@deepseek-ai/dsh-client-ui-primitives` 的 `useAnchoredPosition` 在 0.2.2 线内被移除。官方指南 `docs/upgrade-guide/v0.2.2-alpha.2/css-anchored-menus/guide.md` 自 alpha.2 起要求客户端 UI 迁往 **CSS Anchor Positioning**；但**导出面实际落地时点晚于指南标题版**。逐版 `npm pack` 解析 `lib/index.js` 运行时 `export {}` 块实测（2026-11-16）：

| primitives 版本 | `useAnchoredPosition` | `useDismissOnOutsidePointer` | 图标（Icon* 系列） |
|---|---|---|---|
| 0.2.0-rc.1 ～ 0.2.1-rc.5 | 存在 | 存在 | 存在 |
| 0.2.2-alpha.2 / alpha.3 / rc.1 | **仍存在** | 存在 | 存在 |
| **0.2.2-rc.2 / rc.3** | **已移除** | 存在 | 存在 |

三条读表纪律：

1. **删除边界 = `0.2.2-rc.2`，不是指南目录名所示的 alpha.2**。peer/engines 上下界一律以真包导出面实测为准，不照指南标题版抄——抄了会误挡 alpha.2/alpha.3/rc.1 三个仍兼容的宿主。
2. **同线内还有"只删一个"的缝**：`useDismissOnOutsidePointer` 全程保留。迁移时不要顺手把同批 import 的其它 primitives 符号一并 shim/删除——给仍存在的导出写兜底就是死代码（事故 PR #16 原样犯过）。
3. **内部实现演进 ≠ 公开契约变更**：以 `export {}` 块具名清单为准，不以源码文件增删、内部 hook 名为准。

## 二、被删后的正确修复路线（事故裁决，三选一里只有一个对）

| 路线 | 做法 | 判定 |
|---|---|---|
| A 运行时探测 + 自实现 fallback | `typeof host.useAnchoredPosition === 'function' ? host : local` | ❌ 探测第三方包私有导出会让 peer 门禁**永久失效**，后续每次契约破坏被吞成静默降级；fallback 必然行为退化（丢 margin/视口夹取/多 side） |
| B 代码不动、peer 截到删除版之前 | `>=x <0.2.2-rc.2` | ❌ 新宿主**直接拒载**，功能整个消失——"不崩"不等于"可用" |
| C **迁 CSS Anchor Positioning + 声明跟随迁移** | 删 hook 引用，`anchor-name`/`position-anchor`/`anchor()`；peer 翻到 `>=0.2.2-rc.2 <0.3.0-0`（或作者版 `^0.2.2-rc.3`，includePrerelease 下二者对 rc.2 的差别见 §四） | ✅ 纯 CSS 不依赖 primitives 导出，天然跨宿主线 |

C 的两条工程细则（PR #19 落地版）：

- **能力降级只允许探测 W3C 标准能力**（`CSS.supports('anchor-name: --probe')`），不允许探测包私有导出。桌面宿主 Electron ≥44（Chromium ~150）原生支持；但 `dsh --profile web` 远程部署态跑在**用户自选浏览器**里，锚点支持无保证——降级分支按此态保留。
- **测试栈盲区要显式补**：本类崩溃能穿过 CI，是因为 vitest `environment:'node'` 不执行 tsx 里的宿主 import。防线 = 纯 node 的「源码具名 import × 真包 export 块」断言测试（可参照 PR #19 `tests/export-contract.spec.ts`），外加产物字符串断言。

## 四、peer 写法纪律四条（本轮事故沉淀，全库通用）

1. **宿主判定口径**：`semver.satisfies(runtime, range, { includePrerelease: true })`，只读 `@deepseek-ai/dsh`/`dsh-*` peers；插件若有 `engines.dsh` 则它单独裁决、peers 全忽略（§25.2）。
2. **caret 是跨线假声明**：`^0.2.0-rc.2` 在 includePrerelease 下命中 `0.2.2-alpha.2/rc.3`。依赖某导出的插件，peer 必须写成显式上下界 `>=首版 <删除版`。
3. **上界 `-0`**：`<0.3.0` 会放行 `0.3.0-rc.*`，写 `<0.3.0-0` 才挡得住。
4. **代码与声明成对改**：迁走旧 API 的同一次提交里把 peer 翻到新线；只改一边都是非法态（改代码不改 peer = 放行旧宿主但用错声明；改 peer 不改代码 = 拒载能跑的或放行崩的）。
