# DSH v0.1.5 迁移补充指南（实战校准）

> 来源：dsh-context-compression-improved 插件完成 0.1.1-rc.2 → 0.1.5-rc.2 全量适配后的复盘。
> 定位：[v0.1.5-migration.md](v0.1.5-migration.md) 的**补充**——以下是迁移指南正文没有覆盖、但在真实插件适配中逐一踩到并验证的事实。
> 每条都附适配写法与出处（本仓库 compat/0.1.5 分支对应提交）。

---

## 一、cordis 插件启动语义变化（影响面最大，文档未记录）

**现象**：`await ctx.plugin(X)` 在 0.1.5（cordis 4.0.2）不再等待插件就绪——`Service` 构造后服务仍未落到 `ctx`，`ctx.get('tokenMeter')` 返回 `undefined`。0.1.1 时代这样写是可以的。

**适配**：所有程序化挂载必须 `.await()`：

```ts
await ctx.plugin(TokenMeter).await()   // 0.1.5 必须显式等待
```

**波及面**：测试套件（runtimeContext / 每个 `new Context()` 的挂载序列）、e2e smoke 脚本。逐个 `plugin(...)` 调用点检查，漏一个就是"服务 undefined"类 TypeError。

---

## 二、TokenMeter 依赖 SessionProjectionRegistry 先行挂载

0.1.5 的 `TokenMeter` 声明 `static inject = ['sessionProjections']`；`sessionProjections` 由独立包 `@deepseek-ai/dsh-session-projection` 提供。在它之前挂 TokenMeter 会静默不落服务（不报错、`ctx.tokenMeter` 永远 undefined）。

```ts
await ctx.plugin(SessionProjectionRegistry).await()
await ctx.plugin(TokenMeter).await()
```

注意：`mountAgentLoopTestDependencies(ctx)`（testkit）**已经内部挂载** Registry——之后再挂一次会抛 `service "sessionProjections" has been registered`。判据：紧邻 testkit mount 的上下文不要再显式挂。

## 三、`session/event` firehose 不播 seed 事件（Native 自动压缩审计断裂）

**现象**：0.1.5 的 Native auto-compact 通过**会话 seed-reopen** 落盘（压缩后的日志以构造器 seed 形式进入新 facade）。官方文档明确 "constructor seeds do not emit"——`compaction/summary` 事件**不会经过 `session/event` firehose**，但 `session.snapshotEvents()` 里能看到。

**影响**：所有依赖 `ctx.on('session/event')` 观察 compaction 系事件的插件（审计、locator、统计）在 0.1.5 上静默失明。

**适配**：改为快照扫描 + 去重。例如在 `pruneSession` 入口、pre-step 边界（`await next()` **之后**，因为 BasicCompactionEngine 自己的 pre-step 才是提交方）扫描：

```ts
for (const event of sessionEvents(session)) {
  if (event.type === 'compaction/summary') emitAuditOnce(session, event.seq, event.data)
}
```

用 `WeakMap<Session, Set<seq>>` 防重。出处：dsh-context-compression-improved `index.ts` 的 `scanForSeededNativeSummary`。

## 四、设置面板席位：0.1.5-rc.2 三个槽全部声明——选一个，钉测试（2026-09-17 实测校准）

> ⚠️ **本节曾断言"0.1.5-rc.2 把 `settings.plugin.item` 改名为 `settings.plugins.tab`、旧名注册抛错"，实测有误。** 源码核验（`ui-settings-plugins/src/client/index.ts`，dsh-v0.1.5-rc.2 与 v0.1.6-alpha.1 一致）：`settings.plugin.item`（keyed，内置"配置" tab 的卡片列表子槽）、`settings.plugins.tab`（list，独立 tab）、`settings.section`（list，顶层分节）**三者都声明**。注册旧名不抛错；真正的坑是下面这个。

**实测翻车案例（dsh-thinking-levels 2.0.0-beta.3）**：基于"旧槽已死"的误判做双注册，结果同一张设置面板在 0.1.5 上渲染两次——"配置"列表一张卡 + 一个独立 tab。0.1.5 上不存在"槽 A 声明、槽 B 未声明"的互补关系，双注册只剩重复渲染副作用。

**适配**：一个面板只注册**一个**席位（小型配置 → item 卡片；大型面板 → tab 或顶层分节），并用 TDD 钉死（见 [settings-seat-pinning.md](settings-seat-pinning.md)）。`id`/`key` 双写兼容 Desktop list 与 CLI keyed 仍有效，可保留。

## 五、服务注入：shell 常备服务走声明式 inject；懒取 `ctx.get()` 才是静默消失的真凶（2026-09-17 实测校准）

> ⚠️ **本节曾建议"只声明 `['slots']`，其余服务在 apply 内懒解析"。实测该做法本身是竞态事故源**（dsh-context-compression-improved 0.1.0：apply 先于 settings 客户端激活运行，`ctx.get('settingsScope')` 返回 undefined → 早退 → **全部设置入口静默消失**）。挂起只发生在声明了宿主根本不提供的服务时；对 shell 常备服务，声明式注入是官方模式且不会挂起。

**校准后的适配**：

- `slots` / `locale` / `settingsScope` 等设置 UI 必需的 shell 常备服务 → **声明式** `export const inject = ['slots', 'locale', 'settingsScope']`，cordis 等待就绪后 apply（官方 ui-agent-preset、实测 dsh-thinking-levels 在 0.1.5-rc.2 均如此）；
- **可选服务**（缺席是合法状态，如 `connection`）→ 才用 `ctx.get()` + 功能级降级，缺失时响亮 warn，不注册半个面板；
- 无论哪种，席位注册必须配 TDD 钉死测试（[settings-seat-pinning.md](settings-seat-pinning.md)），入口消失/重复在 CI 直接红灯。

## 六、peer 范围的 semver 预发布陷阱

`">=0.1.1-rc.2 <0.2.0"` **不包含** `0.1.5-rc.2`——semver 规则：预发布版本只满足同一 `[major,minor,patch]` 元组上声明了预发布比较器的范围。`0.1.5-rc.2` 与 `0.1.1-rc.2` 不同元组，被排除。

**后果**：与官方包的 `^0.1.5-rc.2` 求交集为空，pnpm 安装直接 `ERR_PNPM_NO_MATCHING_VERSION`（报错里显示的合并范围形如 `>=0.1.5 <0.2.0-0`）。

**适配**：上限用 `-0` 后缀（社区惯例，dsh-input-traffic/dsh-thinking-levels 均如此）：

```json
"@deepseek-ai/dsh-invariants": ">=0.1.5-rc.2 <0.2.0-0"
```

同步检查所有硬编码 peer 断言（package-contract 测试、verify-release 脚本）。

## 七、可复用的宿主能力接缝（下拉选择宿主已配置的供应商/模型）

不要让用户重复填 provider/model——宿主已配置的 LLM 路由可以从服务里读：

| 能力 | 接缝 |
|---|---|
| 供应商目录（含自定义分组） | `ctx.llm.listProviders() → {id, name}[]` |
| 每供应商模型 | `await ctx.llm.listModels(providerId) → {id, name}[]`（缺席/哑火时回退 `listConfigurableProviders()` + `discoverModels(settingsNs, {provider})`，后者对已配置路由只读本地知识、不触网） |
| 当前默认模型 | `ctx.get('agentDefaultModel')?.currentSelection?.() → {provider, model}`（可选服务，缺席不得抛错） |
| 送达设置卡片 | `webServer.register({ kind: 'exact', path: '/api/<plugin>/xxx', handler })`；客户端 `fetch('/api/<plugin>/xxx')`（0.1.5 客户端 API 前缀是 `/api/`） |

参考实现：dsh-perm-gate `src/receiver-info.ts`（纯投影、永不抛错、单组失败内联上报）+ `src/events.ts` 路由注册；dsh-prime-memory `src/llm.ts` `resolveModelRoute`（显式配置 > 宿主默认选择，逐字段回填）。

**注意**：`webServer` 缺席时要响亮 warn 但不致命（pitfall #6227 的运行时检测模式）；不要用 `connection.rpc.handle`（0.1.5-rc.1/rc.2 静默 405，pitfall #6337）。

## 八、仓库卫生：autocrlf 会击穿 SHA 钉死的资产

`core.autocrlf=true` 且无 `.gitattributes` 时，checkout 会把 `tokenizer.json` 转成 CRLF，SHA-256/字节数校验全部失败（报 "failed SHA-256 verification"）。且 `git checkout <ref> -- path` 在 blob 未变时**不会重写工作区文件**——修复要先删后取：

```gitattributes
packages/runtime/assets/** -text
```

```sh
rm -rf packages/runtime/assets && git checkout -- packages/runtime/assets
```
