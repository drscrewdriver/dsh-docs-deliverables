> 对比基线：`dsh-v0.1.7-rc.2`（`477b4f4205`）→ `dsh-v0.2.0-rc.1`（`4878cdabd8`，2026-09-28，PR #5387），261 commits。

## 〇、先说结论

**0.1.7 → 0.2.0 没有 API 层面的破坏性变更。** manifest 契约、settings API（`configure` / `.volatile()` / 席位）、
加载器 / HMR / slot 机制、会话格式 V4 全部未动。版本号跨到 0.2 的直接原因是 **peer 范围世代门槛**：
`<0.2.0-0` 排除一切 0.2 预发布版，把 0.1.7 线插件挡在 0.2.0-rc.1 宿主之外——这是生态强制升级的机制位。

实际要动手的事，按优先级：

| # | 事项 | 级别 | 预计耗时 |
|---|------|------|----------|
| 1 | peer 范围改 `>=0.2.0-rc.1 <0.3.0-0` | 🔴 必做（不做无法安装） | 5 分钟 |
| 2 | 复核 Schedule 三 id 引用（`time-context` / `schedule` / `ui-schedule`） | 🟡 有则必改 | 10 分钟 |
| 3 | 复核 `displayTitle` / `SessionNode.title` 消费（空串语义） | 🟡 有则必改 | 10 分钟 |
| 4 | 适配 `forkSession` / composer 提交契约新签名（实现者） | 🟢 兼容扩展 | 视实现 |
| 5 | （可选）接 `ctx.otel` / `ctx.productAnalytics` 新服务 | 🟢 新能力 | — |

## 一、peer 范围世代门槛（🔴 必做）

**现象**：0.1.7 线插件在 0.2.0-rc.1 宿主上 `dsh plugin install` 直接报
`installation rejected` + `IncompatiblePlugin`，且**什么都没装**（preflight 在 pnpm 运行前拒绝；
安装后复查不满足时整个回滚到装前状态）。

**原因**：`evaluatePluginCompatibility`（`packages/boot/app-boot/src/plugin-compatibility.ts:61`）对
`@deepseek-ai/dsh` / `@deepseek-ai/dsh-*` peer 用 `semver.satisfies(runtimeVersion, range, { includePrerelease: true })` 校验。
semver 比较中数值型预发布标识 `0.2.0-0` **小于**字母型的 `0.2.0-rc.1`，因此 `0.2.0-rc.1` **不满足** `<0.2.0-0`。

**动作**：

```jsonc
// package.json
"peerDependencies": {
  // 旧（0.1.7 线）
  // "@deepseek-ai/dsh": ">=0.1.7-rc.1 <0.2.0-0"
  // 新（0.2.0 线）
  "@deepseek-ai/dsh": ">=0.2.0-rc.1 <0.3.0-0"
}
```

- **跨线选项**：0.2.0-rc.1 对 0.1.7 插件 API 完全兼容，可声明 `">=0.1.7-rc.1 <0.3.0-0"` 同时服务两条线；
  但 0.3.0 一旦出现真正契约换代，宽范围会把失败从"安装被拒"推迟到"运行时崩溃"——自行承担跨线测试义务。
- **仓库内开发期**：内部依赖写 `workspace:^` / `workspace:*`，校验时被替换为运行版本本身，不受影响；
  发布时 pnpm pack 自动改写为 `^0.2.0-rc.1`。
- **豁免**：按插件 `name@version` + 运行版本精确配对（宿主工具措辞是 "risk crashes and data loss"）。
  它是用户侧逃生门，不要当发布策略。

## 二、Schedule 默认组合移除（🟡 有引用则必改）

0.1.7-rc.2 里 `disabled: true` 躺在 web-app bundle 中的 `time-context` / `schedule` / `ui-schedule`
三行被**整行删除**，迁入 optional bundle `@deepseek-ai/dsh-experimental-schedule-bundle`。

**自检**：在插件源码与随附的 profile patch 里 grep 这三个 id；在代码里 grep `schedule_`（工具名前缀）与 `ctx.get('schedule')`。

**有引用时的改法**：

1. patch 引用（`dsh.profile.patch` / `--patch` overlay）：文档注明"需先在 Plugins 页启用 Schedule bundle"，
   或把 bundle 写进 `dsh.profile.bundles`；bundle 未启用时 loader 警告 `patch: entry <id> not found`，行不生效。
2. 工具依赖（`schedule_*`）：能力探测代替假设——
   ```ts
   const schedule = ctx.get('schedule')
   if (!schedule) { /* 降级路径：隐藏入口 / 提示 opt-in */ }
   ```
3. 数据消费（逐步 durable clock 消息、Automation tasks 页）：默认组合不再产生新消息；存量数据保留在 Schedule 域。

**无引用**：无需动作。默认组合省掉的 4 个 tool schema + 每步一条 clock 消息对你是纯 prompt 减负。

## 三、`displayTitle` 空串语义（🟡 有消费则必改）

`SessionRowOwnerProps.displayTitle` 与 `SessionNode.title`（`tree.ts sessionTitle()`）不再兜底
project basename / Session id，**未命名会话返回空串**；宿主渲染层用 `t('session.untitled')` 兜底，
插件侧没有这个兜底。

**自检**：grep `displayTitle`、`SessionNode.title`、`sessionTitle`。

**改法**：

```tsx
// 旧：假设非空
const label = props.displayTitle;
// 新：补兜底
const label = props.displayTitle || t('session.untitled'); // 或你自己的"未命名会话"文案
```

rename 快捷键入口现在传**原始标题**（可能空串）——做重命名对话框的插件把空串当"未命名"处理。

## 四、兼容性扩展（🟢 实现者适配，调用者免改）

两组签名扩展**向后兼容**——你只调用不动代码就没影响；只有**实现/override 这些接口**的插件要适配：

1. **`forkSession`**：`(sessionId) => Promise<void>` → `(sessionId, onCreated?) => Promise<SessionId>`。
   `onCreated(childId)` 在继承标题重命名**之前**回调。位置：`ui-workspace/src/client/navigation.ts`、
   `session-controller/src/client/contract/sessions.ts`。
2. **composer 提交契约**：`SessionInput.submit(mode?, source?)`、`ComposerKeyboard.submit(mode, source?)`、
   `InputEvent 'enter'` / `SubmitAttempt` 新增可选 `submission` 字段；新增 `MessageSubmission` /
   `MessageSubmissionState` 类型（`ui-conversation/src/client/contract/composer-submission.ts`）。
   做"提交来源感知"的插件现在有官方挂点。

另两处局部变化：`TextShimmer` DOM 重构（嵌套包装 + `data-shimmer-decoration`，只影响覆盖其样式的插件 UI）；
`session-log-deepseek.Config.enabled` 改 `Volatile<boolean>` 且由可选变**必有**（类型层适配，热更新语义见下）。

## 五、可选采用的新能力（🟢）

| 能力 | 入口 | 说明 |
|------|------|------|
| 共享 OTel 上报 | `ctx.otel.createEventReporter(options)` / `createSessionLogReporter(options)` | 官方方向：插件不再自组 OTel SDK，改用共享工厂（参考 `session-telemetry-otel` / `product-telemetry-otel` 的重写）。字节限额 `maxRequestBytes` ≤ 4,000,000 |
| 产品埋点 | `ctx.productAnalytics?.report(event)` | **仅 desktop profile 挂载**，普通 Web `ctx.get()` 返回空——必须 `?.` 判空。事件类型在 `tool-cordis` api-catalog（`ProductEvent` / `ProductEventMap`） |
| 设置热更新范式 | `.volatile()` + 请求路径上 `config.x.get()` | 官方收敛建议：用户可即时开关的偏好用 volatile 声明，不要启动时缓存布尔值（`session-log-deepseek.enabled` 是范例：General 设置新开关改完下一请求即生效） |
