# 元讨论分析成果（Meta-Discussion）—— 社区治理/提案/RFC/契约/广告反馈


## 一、机制说明（本成果如何产生）


### 1. 候选粗筛：关键词打分（锚点校准）


以两条用户指定锚点定义『元讨论』边界：
- **#2714**（RFC 插件互操作标准 v0.15：Manifest/Capability/契约/社区讨论稿）→ 标准契约 RFC 类
- **#5777**（社区反馈·第二轮：伪装广告/自顶污染首页，附证据清单）→ 治理反馈类

关键词词典按 5 类加权（标题命中 x3），正文前 4000 字符参与匹配：

| 类别 | 关键词（示例） | 权重 |
|---|---|---|
| 治理反馈 | 广告/自顶/举报/污染/引流/假图/spam/abuse | 5 |
| 标准契约 RFC | rfc/互操作/manifest/契约/contract/standard/草案/draft/认证 | 3-5 |
| 生态基础设施 | registry/收录/scaffold/plugin check/market/分发 | 2-4 |
| 社区流程渠道 | welcome/read before posting/反馈入口/翻译/guidelines | 2-4 |
| 功能/API（区分项） | api/proposal/seam/feature | 低（用于识别噪音） |

全库 5779 篇打分 → 得分 ≥8 得 **966 候选**；聚焦得分 ≥15 得 **314 篇**。

### 2. 精细分类：本地规则归类


对 314 篇按 5 类词典二次计分归类（B标准>A治理>E流程>C基建>D功能），得到初步类别分布：
标准契约RFC 137 / 功能API提案 111 / 生态基建 33 / 社区流程 25 / 治理反馈 8。
规则分类有噪音（标准契约类混入功能提案）。

### 3. LLM 复核：jq 拆分 + 本地 8200 Qwen 逐条判定


- 使用 jq 语义拆分（`. [] | {num,title,score,cls}` + 每 30 条一块）→ `meta-chunks/chunk-001..011.json`
- 每块 POST 到 `http://192.168.100.242:8200/v1/chat/completions`（Qwen3.6-35B-A3B，keyfree，`response_format: json_object`，温度 0.1）
- 判定标准：帖子的**讨论对象是社区/生态本身如何运作**（治理/标准/基建/流程）→ meta=yes；否则（具体功能提案/插件展示/bug/问答）→ meta=no

结果：**314 篇投票，111 篇确认元讨论（meta=yes），203 篇驳回**。
驳回构成：功能提案 116 / 插件展示 42 / bug 26 / 其他 17 / 问答 2 —— 说明初筛关键词把『功能 proposal』当成了社区提案，LLM 复核是必要环节。

### 4. 标题相似去重


对 111 篇按标题归一化聚类（同题多号刷屏帖只留编号最小者）。典型：『多插件架构会放大 LLM 幻觉吗』9 个账号重复发 → 并 1。

**最终成果：103 篇独立元讨论**（另 8 条为重复刷屏）。
